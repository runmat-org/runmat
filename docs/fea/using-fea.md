# Using FEA

This guide builds and runs a small structural study, then shows generated inputs, sweeps, and cluster placement. The complete repository examples are checked as part of the release workflow.

## A Complete Study

Save the following as `bracket.fea` beside `geometry/box.brep`:

```fea
geometry bracket {
    file = "./geometry/box.brep"
    units = m

    region body : solid {
        select id "solid_000001"
        expect exactly_one
    }
    region support : face {
        select id "face_000001"
        expect exactly_one
    }
    region load_face : face {
        select id "face_000002"
        expect exactly_one
    }
}

mesh bracket on geometry.bracket {
    tetrahedra {
        order = linear
        target_size = 0.75 m
        maximum_deviation = 0.05 m
    }
}

material steel {
    mass_density = 7850 kg/m^3
    elastic {
        youngs_modulus = 200 GPa
        poisson_ratio = 0.3
    }
}

model loaded_bracket {
    assign material.steel to geometry.bracket.region.body
    constraint fixed_support {
        structural.fixed { target = geometry.bracket.region.support }
    }
    load service_force {
        force on geometry.bracket.region.load_face = [0, -1, 0] kN
    }
    load_case service { include load.service_force }
}

study structural_static_experimental {
    geometry = geometry.bracket
    mesh = mesh.bracket
    model = model.loaded_bracket
    require formulation = experimental
    analysis static { structural static {} }
    output displacement = analysis.static.field.node.displacement
    output von_mises = analysis.static.field.element.von_mises_stress
}
```

This separation is deliberate:

- geometry declares exact topology and stable region selection;
- mesh declares discretization controls, not physical properties;
- material declares constitutive data;
- model assigns that material to the solid region and conditions to face regions;
- study chooses the model and procedure and names the fields to publish.

## Check, Plan, Run

```sh
runmat fea check bracket.fea
runmat fea plan bracket.fea
runmat fea run bracket.fea
```

Use `--json` for automation. `check` parses and type-checks the entire source graph but does not mesh or solve. `plan` prints the canonical logical phases and selected root. `run` realizes exact geometry, meshes, compiles assignments and procedure state, executes the solver, and publishes a typed result manifest.

The short forms behave the same way:

```sh
runmat check bracket.fea
runmat run bracket.fea
```

If the root module declares several studies or sweeps, selection is explicit:

```sh
runmat fea run qualification.fea --study bracket_static
runmat fea run qualification.fea --sweep load_envelope
```

## Inspect Geometry Before Authoring Regions

From `.m` code:

```matlab
facts = geometry.inspect("geometry/bracket.step");
part = geometry.load("geometry/bracket.step", "Units", "millimeter");
regions = geometry.listRegions(part);
mesh(part);
```

Use inspection to choose source aliases, imported names/tags, persistent identities, or feature results. Do not infer a face id from file order. A region declaration records both the topology role and cardinality expected by the model.

## Generated Time History From `.m`

Put the function in `impactPulse.m`:

```matlab
function y = impactPulse(t, magnitude)
arguments
    t (:,1) double
    magnitude (1,1) double
end
y = magnitude .* sin(pi .* min(t ./ 0.01, 1));
end
```

Import that exact file and use it inside a model:

```fea
import function impactPulse from "./impactPulse.m"

model impact_model {
    signal pulse : force over time {
        generated by function.impactPulse {
            arguments { magnitude = 1000 }
            sample from 0 s to 0.1 s at 1 kHz
            interpolation = linear
            extrapolation = reject
            tolerance = 1e-6 N
        }
    }
    excitation impact {
        force {
            target = geometry.bracket.region.load_face
            signal = signal.pulse
            direction = global([0, -1, 0])
        }
    }
    load_case impact { include excitation.impact }
}
```

The import is not a loose callback name. RunMat freezes the exact source definition and signature, then schedules deterministic sample chunks before solver execution. The numerical kernel receives a materialized physical signal rather than invoking user code while assembling or solving.

Generated response spectra and random-excitation spectra use the same imported-function boundary. Their declarations continue to own the physical axis, units, damping or channel shape, interpolation, extrapolation, and evidence.

## Study Inputs And Sweeps

Declare a bounded input inside the study:

```fea
input service_load : force {
    minimum = 0 N
    maximum = 2 kN
}
input damping : real = 0.02
```

Then define axes or named cases:

```fea
sweep envelope : study.response {
    axis service_load {
        nominal = 1 kN
        proof = 2 kN
    }
    axis damping {
        low = 0.01
        nominal = 0.02
    }
    combine = product
    output peaks = collect(case.output.peak_displacement.value)
    output fields = retain_each(case.output.displacement)
}
```

Sweep expansion is deterministic. RunMat checks every value against the declared input type, units, range, and default/required status before submitting cases. Independent cases may run concurrently; result ordering follows stable case identity rather than completion time.

## Local And Cluster Runs

Local execution is the default:

```sh
runmat fea run bracket.fea --json
```

Use the same checked source on a configured cluster:

```sh
runmat fea run bracket.fea \
  --cluster engineering \
  --project 7a7d4d37-f0ae-4a6b-a0f8-013a04e0a9d5 \
  --queue batch \
  --workers 8 \
  --trust-identity sha256:<endpoint-fingerprint> \
  --json
```

`--detach` returns after submission. `--idempotency-key` supplies a stable retry identity. Every explicit `--cluster` run requires `--trust-identity`; `--project` is a project UUID. Other remote-only options are rejected without `--cluster`. A named authored profile can also route remotely when project configuration supplies its pinned trust identity. Credentials and routing are project/runtime configuration; they are not embedded in the physical study.

A typed `execution` declaration is optional. Use it for portable placement preferences, resource limits, case/frequency fan-out, cooperative operator partitioning, and checkpoint requirements. Small local analyses need none of those declarations.

## Results And Rendering

A published result retains the checked study definition, exact geometry and mesh identities, resolved workloads, numerical receipts, evaluated authored outputs, and field bindings. Fields are retrieved by their authored output and step/sample identity; bounded pages avoid loading unrelated payloads.

Selection and rendering are separate:

```matlab
stress = stepResult.field(fea.OutputField.named("von_mises"));
plot(stress);

solverMesh = stepResult.mesh();
mesh(solverMesh);
```

`plot` and `mesh` remain the ordinary RunMat rendering functions. FEA-specific APIs select typed data; they do not own a second plotting subsystem or accept an untyped field-name option inside the renderer.
