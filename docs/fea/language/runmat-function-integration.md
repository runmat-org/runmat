# RunMat function integration

Use a `.m` function when an input requires bounded computation that does not belong in the
declarative language. The import names both the symbol and its file:

```fea
import function impactPulse from "./impactPulse.m"
```

The imported file must define the named function entrypoint. RunMat checks its arguments, result,
effects, capabilities, source digest, and executable revision through the ordinary project
pipeline. Scripts, ambient workspace reads, suspension, unapproved effects, ambiguous definitions,
or an incompatible result fail before materialization.

## Generated signals

```fea
model impact_test {
    signal pulse : force over time {
        generated by function.impactPulse {
            arguments {
                peak = 1 kN
                duration = 6 ms
            }
            sample from 0 s to 50 ms at 100 kHz
            interpolation = linear
            extrapolation = reject
            tolerance = 1e-5 N
        }
    }
}
```

The signal declaration owns physical quantity, domain, sample range, interpolation, extrapolation,
and tolerance. The `.m` function computes values for admitted samples; it does not mutate the
model, select geometry, or run inside a solver kernel.

Sampling is deterministic. RunMat may divide the sample domain into portable chunks and place
those chunks locally or on cluster workers. The materialized signal records the function source,
arguments, sample contract, result digest, and execution evidence so local and remote paths can be
compared exactly.

## Generated spectra

Response spectra and random-excitation spectra use the same import boundary. Their declarations
still own frequency or period axes, ordinate quantity, damping, response measure, channels,
spectral convention, interpolation, extrapolation, and evidence. A function returns samples; it
does not define those FEA semantics implicitly.

## Generated geometry

A geometry declaration may materialize a typed function result:

```fea
geometry bracket {
    input width : length = 80 mm

    generated by function.makeBracket {
        arguments {
            width = input.width
        }
    }

    region body : solid {
        select output.region.body
        expect exactly_one
    }
}
```

The function result must satisfy the declared geometry-output contract. RunMat admits the result
through the same canonical geometry validation, persistent-topology, region, meshing, caching, and
evidence path as imported or declaratively constructed geometry.

## Editor navigation

Go to definition on `function.impactPulse` opens the imported `.m` function. Signature help and
completion use its checked type. Editing the function invalidates dependent diagnostics and frozen
materializations; an old executable revision cannot silently satisfy the new source import.
