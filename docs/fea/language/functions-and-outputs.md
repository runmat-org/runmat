# RunMat Functions, Generated Inputs, and Outputs

## Exact `.m` Imports

An imported function is addressed by both symbol and file:

```fea
import function impactPulse from "./impactPulse.m"
```

The compiler uses the ordinary frozen RunMat project pipeline to verify the exact definition, arguments, result type, effects, capabilities, source digest, and executable revision. FEA accepts only the callable shape required by the declaration. Captures, suspension, unapproved effects, ambiguous definitions, changed bytes, or a result with the wrong physical shape fail before the solver runs.

## Generated Time Histories

```fea
model impact {
    signal pulse : force over time {
        generated by function.impactPulse {
            arguments { magnitude = 1000 }
            sample from 0 s to 0.1 s at 1 kHz
            interpolation = linear
            extrapolation = reject
            tolerance = 1e-6 N
        }
    }
}
```

The sampled domain, physical quantity, interpolation, extrapolation, and tolerance remain FEA contracts. The `.m` function computes samples; it does not mutate the model or run inside a numerical kernel. RunMat chunks the domain deterministically and schedules the chunks on the same local or cluster execution substrate as other portable work.

Response spectra and random-excitation spectra use the same `generated by function.<id>` boundary. Their surrounding declarations still own axes, units, damping, channel shape, spectral convention, interpolation, and evidence.

## Output Expressions

Outputs select typed analysis fields and apply the shared operation catalog:

```fea
output displacement = analysis.static.field.node.displacement
output displacement_magnitude = magnitude(output.displacement)
output peak_displacement = max(
    output.displacement_magnitude,
    over = geometry.bracket.region.body,
)
```

The field reference selects data; `magnitude`, `max`, and other operations transform or reduce it. Rendering is separate: after execution, pass the materialized field object to ordinary `plot(field)` or the mesh object to `mesh(meshValue)`.

The FEA compiler does not maintain a parallel collection of string-dispatched math functions. It resolves an operation identity and typed FEA overload from the shared RunMat catalog, checks argument and result types, and exposes the same facts to completion and signature help. Sweep-only operations such as `collect` and `retain_each` are typed over case outputs.

Published output fields are content-addressed and page-accessible. Selecting one output does not require loading unrelated result payloads; every page retains study, step, field, sample, mesh, workload, and numerical-receipt identity.
