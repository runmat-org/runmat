# Generated tensor and spatial-field value layout

Status: bounded shared input-layout and deferred-input graph integration. No
formulation, stage or qualification promotion. Arbitrary-mesh generator arguments,
exact preprocessing resources, positive whole-study spatial solves and restart
qualification remain open.

Runtime MATLAB dense arrays use column-major storage. Generator output axes are
sample-leading: `[samples, tail...]`; canonical signal values are sample-major with
row-major tensor tails. A nodal vector therefore stores contiguous components of
node zero, then node one, in the authenticated canonical node order. Previously
only the sample axis was reordered, leaving all nodes' first components before
their second components. Equal-valued fixtures concealed the error.

One physics-neutral conversion now handles scalar/vector, arbitrary tensor and
topology-field real/complex values. It checks positive extents, overflow and exact
cardinality before conversion, allocating only the final reordered value buffer.
The PSD path uses the same conversion and removes its separate matrix transpose;
existing signed imaginary cross-phase evidence must stay unchanged.

Frozen signal admission requires the explicit `sample_major_row_major` value-layout
contract, included in the realization-policy identity. Missing/unknown old layout
contracts are rejected; old sealed values are not silently reinterpreted. Already
canonical authored tables are not reordered. There is no old-object compatibility
path. Core canonical signal-value ownership is extracted into its value module;
the existing public type and serialized representation remain unchanged.

The exact native field callable is `reshape(t * scale, numel(t), N, C)`, with the
authenticated fixture mesh supplying N and declared scalar/vector shape supplying
C. Shared `numel` semantic metadata is corrected from unknown to pure: its current
implementation reads resident array/handle metadata without workspace mutation,
device payload gathering or suspension. Generator admission remains unchanged;
unknown/effectful calls still fail closed. This does not claim GPU execution.

Evidence inventory:

- The distinct-value Tet4/Tet10 node-vector regression fails before correction:
  node-zero Y receives node-one X (`10` instead of `1`). After correction it checks
  every sample, node and component through canonical sealing and solver tables.
- Literal non-square real/complex `[2,2,3]` storage and rank-three tensor tails
  independently check coordinates; invalid extents/cardinalities fail closed.
- Existing scalar/vector and Hermitian complex PSD tests guard unchanged paths.
- Process conformance includes existing vector input plus Tet4/Tet10 nodal body-force
  density and temperature fields. Each field has five samples in three chunks and
  compares every canonical value/digest with independently constructed row-major
  tables across inline, isolated, durable and encrypted-remote task placement.

The process fixture starts from an authenticated canonical mesh and resolves a typed
deferred declaration against it, not a whole authored `.fea` mesh/input execution
graph. Durable task completion
is not failure/replacement restart. Remote generator tasks are not remote whole-study
spatial execution or distributed operators. Physical body-field quadrature/dynamics
evidence remains separately governed; these layout tests do not replace it.

Typed admission is a separate requirement from layout equivalence. Callable admission,
prepared signal validation and transported expectations invoke the shared core physical
signal validator. The process fixtures validate both generated and explicit declarations.
A scalar topology field's entity axis does not turn temperature into a physical vector:
Node1 values may omit a component frame, whereas component-valued fields still require
one. A declared frame remains validated. Shape, approximation evidence and frame
negatives must reject at admission/import, not merely during a later numerical solve.

## Authored topology intent and explicit mesh resolution

Generated declarations may express a physics-neutral study-mesh field:

```fea
signal density : body_force_density over time {
  topology = study_solver_mesh
  location = node
  components = 3
  frame = global
  generated by function.density {
    arguments { }
    sample_points = [0 s, 1 s]
    interpolation = linear
    extrapolation = reject
  }
}
```

The snippet assumes an imported `density` function with the checked generator
signature. The closed locations are node, cell, element, face and edge. All three topology
members are required together; components must be a positive integer. Scalar fields
need no component frame, while component-valued fields require one. Unsupported
selectors, locations, missing members and conflicting declarations reject during
semantic checking. This is generated-field syntax, not direct-artifact admission.
Quantity/action validation remains authoritative; merely declaring a location does
not make a physics formulation support that domain.

`DeferredTopologyField` retains the authored selector without a mesh digest or entity
count. It cannot report a realized cardinality, even when a caller supplies a guessed
count. It is invalid at prepared-input, binding and numerical-materialization boundaries.
`SignalTopologyResolution` creates a separate resolved declaration and exact canonical
mesh binding. Its identity binds the complete authored contract and the mesh-derived
transition. Reopening requires rederivation against the expected authored declaration
and authenticated mesh; a transported resolution is not its own authority. The
authored declaration is never overwritten. Tests reject foreign meshes, changed
selectors and substituted transported declarations.

The native process fixture composes this transition with actual compiled generators
and checks Tet4/Tet10 Node1/Node3 values across the four task placements. It does not
yet prove native whole-study deferred-input scheduling, resource admission, restart,
or cold publication of the authored-to-resolved closure. Those remain required before
advertising executable authored spatial generators. No solver or qualification gate is
promoted by semantic checking or this fixture.

## Frozen deferred callable preparation

`FrozenDeferredSignal` is distinct from an executable prepared materialization. It
retains the original authored declaration, admitted named callable, complete portable
executable, available capabilities and bounded inline-result policy, but no chunks.
Static facts are recovered from the executable's authenticated canonical AnalysisStore
component. Supported analysis/catalog revisions, unique ordered function inventory,
entrypoint, capabilities and existing effect/signature rules are checked. Separately
transported function facts cannot override that component. A self-consistent envelope
is not external authority: transported frozen contracts must match the independently
retained expected intent.

Resolution rederives admission from those same executable facts against the mesh-bound
declaration, preserving invocation/provenance and creating a new materialization identity.
Only then are count-bound chunks and portable requests prepared. Cold validation of a
resolved expectation rederives this chain from original expected intent plus authenticated
mesh; it does not rerun user code. Direct artifact arguments and bound runtime closures
are not admitted by this named deferred-input contract.

The process matrix now exercises actual named field compilation, frozen-contract
serialization/reopening, resolution and canonical values across all four placements.
The ordinary vector fixture still covers a captured anonymous callable. The shared
frozen-project fixture compiler replaces duplicated preparation. These placement
cases remain a fixture-mesh chain, not whole-study spatial solve/restart evidence.
In particular, thermal excitation consumers still require scalar samples: Node1
temperature generator transport does not qualify a thermal Node1 excitation solve.

## Native two-phase input graph

`InputMaterializationPlan` carries either a fully prepared Ready input or original
frozen deferred intent. Source and exact study roots transport that distinction;
they do not manufacture chunks before meshing. Local structural, thermal and acoustic
composition resolves plans against the authenticated mesh before applying canonical
inputs and admitting numerical work. Existing electrical no-generator admission is
unchanged. Remote study and sweep coordinators retain topology-free input/mesh
concurrency; mesh-dependent tasks run only after successful meshing. Sweep identities
and deduplication are resolved within successful mesh groups, not by authored intent
alone. Different request groups returning an identical mesh may repeat input work;
cross-group resolved deduplication is not claimed.

Cold imports retain the original source comparison, then independently derive input
expectations from original frozen intent and returned verified mesh. Numerical
projection checks admitted provenance and exact authored artifact identity/digest/schema
inventory, including rejection of metadata tampering that leaves numerical identity
unchanged. Ready inputs may transport references separately from bytes: producer
closure checks and runtime registered-payload validation remain required; decoding
references is not itself proof of a local byte closure.

The native OCCT test follows checked imported Node3 source through root transport,
constructed CAD, exact meshing and authenticated resolution, executes the named
callable, and rejects its deliberately wrong one-row result. No implicit broadcast
is permitted. This is authority and invalid-shape evidence, not a positive spatial
structural solve. The generator wire currently passes its sample axis and authored
arguments, not mesh cardinality or coordinates; arbitrary-mesh sizing/coordinate
arguments, direct deferred artifacts, exact resource admission, cold positive
whole-study spatial results and failure/replacement restart still need qualification.
