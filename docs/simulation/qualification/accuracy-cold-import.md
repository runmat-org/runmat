# Original-source accuracy evidence at cold import

Status: shared accuracy transport; no family or release promotion.
Owner: Stage 2 accuracy and immutable source authority, with Stage 12 release implications.

## Acceptance boundary

Accuracy import authenticates the report's transport inventory, then admits its actual wire and
canonical materialization profiles before decoding the typed report. The retained source inventory
must match the producing accuracy host's input descriptors. Program preparation, scheduled task
admission and cold accuracy import use the same borrowed-descriptor validator; it does not copy fields.

For every supported receipt family, import decodes the original evaluation request, unique numerical
receipt and optional observation catalog. Their logical identities must match their authenticated
object manifests. The existing family source-context owner validates every remaining original input;
there is no importer-specific list of solver input kinds. Request, authored controls, material context,
mesh, producer, result and observations retain their existing family-specific binding checks.

The shared resource planner rederives the accuracy plan from those original inputs and receipt.
The imported report's evidence must equal the evidence actually available from that receipt. Its
report and publication gate are then recomputed against the authored plan. Changing a measure,
assumptions or evidence scope and recomputing every hash does not make it valid source evidence.

Previously, only CFD imports performed the complete source-evidence and decode-budget check.
All receipt families now use that boundary. Numerical algorithms, scientific references, meshes,
acceptance tolerances, input fields and solver/sample/resource ceilings remain unchanged.

## Independent adversarial witness

The bridge tests use real core structural, acoustic and Tet4/Tet10 thermal results, then transport
accepted or deliberately fabricated reports through the normal serial object and response path.
Every counterfeit has valid canonical encoding, fresh report/evidence/transport identities, an
internally consistent report and a freshly evaluated gate. Import nevertheless rejects:

- a substituted relative measure;
- invented independent-certification assumptions;
- a different evidence scope;
- omitted original source inputs; and
- an invented spatial convergence certificate absent from a thermal receipt.

In the final case, the honest report is indeterminate and blocks publication under a `fail`
unavailable-evidence policy. The counterfeit report is internally satisfied and would allow
publication if its claimed evidence were trusted. Cold
import rejects it rather than accepting its hashes as mathematical proof. The positive source report
still imports, including publication of visibly indeterminate evidence under an explicit
authored `mark_indeterminate` policy.
