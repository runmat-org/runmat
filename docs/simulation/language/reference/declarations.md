# Declarations

## `geometry <name> { ... }`

Parent: module. Labels: one geometry name. Exactly one source form is required: `file`,
`construct`, `generated by function.<name>`, or `from geometry.<name>` with `derive`. A `file`
source also requires its length unit, `units = mm`, `m`, or `in`, because the CAD file is
inspected in those units; without it the checker reports that the geometry needs `units`.
Optional members are typed `input`, CAD-parameter declarations, source-regeneration updates,
regions, and admission assertions. It produces an immutable geometry definition and,
after materialization, a revision-bound canonical geometry artifact.

## `mesh <name> on geometry.<name> { ... }`

Parent: module. Labels: one mesh name and one geometry reference. A source or meshing request is
required. The current volume request is `tetrahedra` with `order`, `target_size`, and
`maximum_deviation`; `maximum_grading_ratio` and `deterministic_seed` use canonical defaults
when omitted. It produces a mesh definition bound to the geometry definition. A study may not pair
it with another geometry.

Local sizing controls are optional inside `tetrahedra`:

| Setting | Form | Meaning |
| --- | --- | --- |
| `cells_across_gap` | integer 1 to 64 | elements through thin gaps and walls narrower than the count times `target_size`, measured between boundary edges and between facing faces |
| `refine <name> { ... }` | block, any number | a local size on one named region of the meshed geometry |
| `on` (in `refine`) | `geometry.<g>.region.<r>` | a `solid`, `face` or `edge` region of the mesh's geometry |
| `target_size` (in `refine`) | length | the local target edge length; must be smaller than the global `target_size` |

Where controls overlap, the smallest size wins, whatever order they are written in. Away from a
refined region the size grows back at `maximum_grading_ratio` per element layer. See
[Local sizing controls](../../meshing.md#local-sizing-controls) for diagnostics and evidence.

## `material <name> { ... }`

Parent: module. Label: one material name. A material must declare a name or at least one physical
capability. Capability blocks cover mechanical elasticity and damping, thermal transport,
electrical conduction, magnetic response, acoustic medium properties, and fluid properties.
Fields are typed quantities or closed constitutive choices. Imported CAD material candidates use
`material <name> from geometry.<name>.cad_material(...)` with explicit `use` and environmental
requirements; provenance does not silently assign the material.

## `model <name>(<parameters>)? { ... }`

Parent: module. Label: one model name. The body may contain inputs, included models, material and
property assignments, sections, layups, orientations, constraints, loads, load cases, signals,
excitations, spectra, random excitations, initial conditions, connectors, and interfaces. A model
has no template or defaults field. Its required content is determined by consuming procedures.

## `study <name> { ... }`

Parent: module. Label: one study name. Required members are `geometry`, `mesh`, `model`, and at
least one `analysis`. Optional members are typed inputs, `execution`, and outputs.
Omitted `execution` uses ordinary local/project policy. A study produces one typed procedure graph and a runnable root.

## `sweep <name> over study.<name> { ... }`

Parent: module. Labels: one sweep name and one study reference. It requires either at least one
`axis` or at least one explicit `case`. Axis sweeps use `combine = product|zip`; `product` is the
default. Axes and cases are mutually exclusive. Optional sweep outputs consume declared study
outputs. A sweep produces stable named cases over study inputs.

## `execution <name> { ... }`

Parent: module. Label: one execution-policy name. Every field is optional. Top-level settings are
`placement` and `backend`; nested blocks are `resources`, `fanout`, `cooperative`, and
`resilience`. The declaration expresses placement constraints and preferences, not physical or
numerical model content. An empty declaration is valid but has no purpose.

## Imports

`import <kind> <name> from "<path>"` appears before declarations. Supported kinds are `geometry`,
`mesh`, `material`, `model`, `study`, `sweep`, `execution`, and `function`. The imported symbol must
exist with exactly that kind. Imports do not re-export the rest of a file.

## Examples

An imported geometry and its mesh are separate declarations. Regions belong to the geometry; mesh
controls belong to the mesh:

```fea
geometry bracket {
    file = "./geometry/bracket.step"
    units = mm
    region body : solid {
        select name "body"
        expect exactly_one
    }
}

mesh bracket on geometry.bracket {
    tetrahedra {
        order = quadratic
        target_size = 2 mm
        maximum_deviation = 0.05 mm
    }
}
```

A material declares behavior; a model assigns it to a physical domain and adds boundary data:

```fea
material aluminum {
    mass_density = 2700 kg/m^3
    elastic {
        youngs_modulus = 69 GPa
        poisson_ratio = 0.33
    }
}

model mounting(region body : region<solid>, region base : region<face>) {
    input body_material : material
    assign input.body_material to input.body
    constraint support {
        structural.fixed { target = input.base }
    }
}
```

The study binds the declarations into one procedure graph. Scale policy is referenced only when the
study needs it:

```fea
execution cluster {
    placement = profile.engineering
    backend = auto
    resources {
        workers = 4..32
        memory_per_worker <= 16 GiB
    }
    fanout { sweep_cases = auto }
    resilience { retries = 2 }
}

study static_check {
    geometry = geometry.bracket
    mesh = mesh.bracket
    model = model.mounting(
        body_material = material.aluminum,
        body = geometry.bracket.region.body,
        base = geometry.bracket.region.base,
    )
    execution = execution.cluster
    analysis solve { structural static {} }
    output displacement = analysis.solve.field.node.displacement
}
```

Imports bind one named symbol of one declared kind:

```fea
import geometry bracket from "./geometry/bracket.fea"
import model mounting from "./models/mounting.fea"
import function impact_pulse from "./impact_pulse.m"
```
