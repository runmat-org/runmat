# runmat-jit

`runmat-jit` owns native compilation policy, publication, execution hosts, runtime feedback, entry cells, invalidation, and executable-memory lifecycle. It consumes verified products from `runmat-native-codegen` and the runtime-owned native ABI. It does not lower MIR, define runtime value storage, own MATLAB semantics, or reconstruct bytecode control flow.

The generic host is split by responsibility: compilation retains executable memory, each invocation owns an opaque generation-checked value arena and ABI frame, callbacks contain panics at the C boundary, and semantic-site execution consumes the immutable Native IR payload through shared runtime operations. Rust `Value` layouts never enter generated code or the native ABI. Unsupported semantic cohorts fail explicitly; they are never replayed through the bytecode interpreter after native entry.

Native ABI schema 3 removed the obsolete required `slow_call` callback: generated code uses the typed semantic-site dispatcher, while the host table retains only implemented lifetime, safepoint, source, and site services. Schema 4 makes resume identity exact to function, block, position, phase, and ordinal. ABI version/layout fingerprints and native cache keys change with either contract, so stale native objects cannot be loaded against a different host table or resume layout.

Invocation lifecycle is separate from one generated-code entry. An invocation owns its value arena, locals, roots, arguments, result window, and exact resume state for its complete lifetime; short-lived C-compatible frame/call/vtable records borrow that stable state only while machine code is active. Generated entry dispatch reads the validated resume block and can re-enter a verified block without replaying the function entry. Structured exception exits materialize Runtime's canonical `MException`, transfer exact edge locals to the innermost active catch, and resume at that verified catch block within the same invocation. Nested catches and `rethrow` retain outer handlers without replaying function entry or completed effects. Later suspension and deoptimization work composes on this owner rather than storing Rust futures, `Value`, or executor objects in the native ABI.

Operators, calls, aggregates, conditions, and MATLAB column iteration stay runtime-owned. The JIT adapters only materialize Native IR operands, preserve requested-output contracts, and select compiled edges. Loop snapshots are invocation-owned: an iterable is evaluated once, retained across compiled backedges, and retired on exhaustion or any edge leaving the natural loop body. Cancellation is checked at every generic semantic site, with exact frame roots, resume points, source spans, and side-effect epochs refreshed around host work.

Call adapters materialize ordinary and comma-list operands in source order, then use Runtime's shared argument-expansion service for cells, output lists, and overloaded object brace access. Static, dynamic, superclass-constructor, and superclass-method calls all enter Runtime's canonical dispatch services with the requested output contract. The VM consumes the same expansion service after decoding its operand stack; neither executor owns a second expansion algorithm.

Function entry and return use Runtime's shared ABI semantics as well. Native IR binds the dependency-neutral argument-validation/default vocabulary to exact native locals; the host projects those locals to fixed-input order, preserves omitted inputs as unassigned, materializes `varargin`, `nargin`, `nargout`, and an empty `varargout`, and delegates validation and output assembly to Runtime. Declared function outputs are read from exact ABI locals in the verified return frame; only synthetic MIR with no declared output ABI consumes the terminator's canonical return vector directly. The VM performs only the corresponding bytecode-slot projection. Closure capture environments remain an explicit unsupported native-entry cohort rather than being confused with ordinary caller arguments.

Index and member adapters likewise consume runtime-owned selector plans, type-preserving reads/writes, object resolution, overload dispatch, and GC barriers. Nested assignments are reconstructed from the changed leaf back to one Native IR root local, and only that updated root is published into the next SSA state. Fixed multi-output indexing preserves discard and comma-list arity; unsupported selector forms fail at their semantic site rather than replaying the function through another executor.

Workspace adapters use the semantic local catalog retained in Native IR rather than VM frame slots. Global and persistent declarations load and synchronize session-owned values by canonical name on every root write, which preserves state across native invocations and across executor boundaries. Workspace-first static-property reads prefer the active workspace or matching named local before shared runtime class resolution. Workspace and environment markers emitted after runtime calls are committed as ordered effect sites but are not replayed, because the preceding call already performed the mutation.

Context-dependent indexing temporaries are retained as verified Native IR recipes and are not eagerly executed. At the actual index site, the host resolves scalar and range `end` expressions once against the base's linear or selected dimension, using Runtime's executor-neutral evaluator and callable path. This prevents placeholder arithmetic and avoids replaying calls or effects embedded in selector expressions; the same evaluator is used by the bytecode VM.

Core owns executor selection and installs the exact immutable executable-unit function registry before entering this host. Its internal forced-generic lane compiles the unit once per invocation, routes nested semantic functions from that same unit back through the same native executor, delegates only genuinely external calls to the previously installed runtime invoker, and never falls back after native entry. Differential tests compare the established executor and forced-generic lane for output arity, nested calls, session globals and persistents, console effects, cancellation, and semantic error identity/source context.

R13 semantic callbacks are deliberately synchronous without starting a nested futures executor. Each runtime operation is polled once inside its `RuntimeContext`; an immediately ready result continues native execution, while `Pending` becomes an explicit unsupported-site exit naming the R14 continuation boundary. This makes accidental suspension observable, prevents executor reentrancy panics, and preserves the no-replay contract until R14 adds real continuation state.

Host-native executable memory is unavailable in a web/WASM process. WASM consumers retain and verify the same portable executable and generic Native IR products; browser execution uses its platform executor rather than embedding a native Cranelift JIT.
